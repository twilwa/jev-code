Phase 2 of TES-46. Prerequisite gate: the phase-1 graph artefact exists in the
tree (`docs/bend2-pilot/evidence/graph/rpg.json`, committed in `a975465`), so
phase 2 was allowed to begin. **No implementation code is written by this

boundaries, Bend 2 entry points), [`02-graph.md`](02-graph.md) (how the graph
was produced and what it does and does not support).

The standing licence constraint from `01-inspection.md` §2 is unchanged and

so this remains research and a local prototype — no publishing, no package
registry action, no redistribution of upstream source beyond this fork, no

## 1. The design decision

### 1.1 The choice

**Native Bend AST**, implemented as a standalone `AstAdapter` object registered
through the existing `AstRegistry`, *not* as a `Dialect` passed through
`adapterFor`.

Rejected: a bounded grammar expressed as a `Dialect`; an extension of the shared
typed IR in `src/lang/core.ts`.

### 1.2 The evidence that decided it

**(a) Bend 2 has no `if` and no mutation, and the shared generator offers both
unconditionally.**

`src/lang/core.ts:249-264` is the block-production generator. Line 259:

```ts
if (depth < maxDepth) {
  criteria.if = 'Conditional statement.';          // :259  — no feature gate
  if (features.range) criteria.range = ...          // :260  — gated
  if (features.foreach && !typed) criteria.foreach = ...  // :261 — gated
  if (features.while) criteria.while = ...          // :262  — gated
  if (features.functions && slot === 'module_body') criteria.function = ... // :263 — gated
}
```

`criteria.if` at `:259` is the only production inside that block with **no**
`features.*` guard. Reassignment is likewise ungated: `src/lang/core.ts:289-293`
builds `Reassign ${id}.` criteria for every non-readonly variable in scope and
offers them whenever at least one exists.

`Features` (`src/lang/core.ts:46`) is
`{ functions, while, range, foreach, list, index, compareStrings, concat }` —
there is no flag for `if` and none for reassignment. A `Dialect` therefore
cannot decline to be offered either construct.

Bend 2 has neither. `bend2/bend.ts:1532` (pin
`7561656155a4285c1e4ccfcb3505ab59524de973`) lists the complete keyword set:
`def, type, law, match, case, do, return, for, exs, where, is, import, Type,
Data, Kind, Quant` — no `if`, no `let`, no `while`. Branching is `match`;
`bendlang/bend` `tests/parse/if_no_else.bend` exists as a parse test precisely
because `if` is not the language's conditional. Bindings are affine and
single-assignment; there is no reassignment form at all.

**(b) Narrowing the grammar would require editing shared upstream code, which is
out of scope.** Adding `features.if` / `features.reassign` to
`src/lang/core.ts` changes the production set for all seven existing dialects.
The brief forbids this twice: "do not rewrite … the language backends" and
"any change to upstream language backends' behaviour" is listed out of scope.
That closes the bounded-grammar route by rule, not only by taste.

**(c) The shared IR cannot express what Bend needs at the binder.**
`ValueType` is `'string' | 'number' | 'bool' | 'list' | 'unknown'`
(`src/lang/core.ts:10`). Bend requires a concrete per-binder type (`U32`,
`String`, `Unit`, `IO(Unit)`) and a copyability annotation. Probe evidence
below: `x : U32 = 21` used twice **fails** type-checking, `+x : U32 = 21` used
twice passes. The `+` is load-bearing and has no representation in `ValueType`
or in `Stmt`'s `assign` node (`src/lang/core.ts:30`). Adding one is again an
edit to shared code.

**(d) There is an existing precedent for a native adapter.**
`src/ast-adapters.ts:23-26` defines `pythonAstAdapter` as a plain `AstAdapter`
literal, and `src/ast-adapters.ts:30` registers it directly in the registry
constructor, *before and separately from* the `bundledAstAdapters()` loop that
carries the `Dialect`-derived adapters. Graph node
`register default python adapter_d2460624`
(`src/ast-adapters.ts::AstRegistry::constructor`) describes exactly this:
"Seeds the registry with the built-in Python syntax-tree adapter". Python is
generated by hand-built tree code in `src/python-ast.ts`, not by
`generateProgram`. A native Bend adapter is the same shape of thing.

### 1.3 Probe evidence

18 probes were run against the real pinned Bend checker before choosing.
Driver `evidence/design-probe/check.mjs`, runner `run-all.sh`, raw output
`evidence/design-probe/probe-output.txt`. Environment: Node v24.21.0, Linux
x86_64, CPU-only, no Bun, no GPU, no API key, no paid resources. Each probe
reports `PARSE` (`Bend.book_load`), `TYPE` (`Bend.book_valid`), `OWNED`
(`Comp.book_owned`) and the hole counts separately, so the three stages are
never collapsed into one verdict.

| Probe | What it tests | PARSE | TYPE | OWNED |
| --- | --- | --- | --- | --- |
| p1 `io-print` | `do IO<Unit>:` + `IO.print` | ok | ok | ok |
| p2 `typed-fn-linear` | `for a: U32` param used once | ok | ok | ok |
| p3 `unused-param` | parameter never used | ok | **ok** | ok |
| p4 `param-used-twice` | plain param used twice | ok | **FAIL** `a (consumed more than once)` | — |
| p5 `bool-match` | `match b: case True{} / case False{}` | ok | ok | ok |
| p6 `do-let-seq` | plain `x : U32 = 40` used once | ok | ok | ok |
| p7 `two-prints` | `u : Unit <- IO.print(…)` sequencing | ok | ok | ok |
| p8 `copyable-param` | `for +a: U32` used twice | ok | **ok** | ok |
| p9 `copyable-string` | `for +s: String` used twice | ok | ok | ok |
| p10 `let-reuse` | plain `x : U32 = 21` used twice | ok | **FAIL** | — |
| p11 `copyable-let` | `+x : U32 = 21` used twice | ok | **ok** | ok |
| p12 `assign-via-param` | helper def taking a copyable param | ok | ok | ok |
| p13 `arith-nested` | `U32.mul(U32.add(a, 0), b)` | ok | ok | ok |
| p14 `compare-bool` | `Bool.show(U32.is_eq(a, 6))` | ok | ok | ok |
| p15 `string-concat` | `String.append(s, "cd")` | ok | ok | ok |
| p16 `while-as-recursion` | recursion over `Nat` | ok | ok | ok |
| p17 `inline-typed-def` | `def f(a: U32, b: U32) -> U32:` | ok | **ok** | ok |
| p18 `inline-copyable-param` | `def dbl(+a: U32) -> U32:` | ok | ok | ok |

Three findings from this table drive the tickets:

1. **p3 vs p4: Bend 2 bindings are affine, not strictly linear.** Dropping a
   binder is accepted; using it twice is not.
2. **p4 and p10 fail at `book_valid`, not at `book_owned`.** Linearity is
   enforced by the type checker. This matters for the three-claims rule: a
   linearity rejection is a **typing** result, and must never be reported as a
   parse result or as evidence of semantic correctness.
3. **p17 shows the inline `def f(a: T) -> R:` form type-checks with no separate
   `law` block.** The emitted subset can therefore avoid generating `law`
   declarations entirely, which removes an entire second grammar from scope.

Two probes were corrected after failing for reasons that were my error, not the
language's, and both corrections are recorded rather than silently fixed:
`U32.eq` does not exist (the Base prelude defines `U32.is_eq`, `base.bend:1418`),
and `x : +U32 = 21` is a parse error — the copyable do-let form is `+x : U32 = 21`.

### 1.4 Scope assessment — does this choice materially change the work?

**No, and here is the reasoning rather than the assertion.** The deliverable
remains: one adapter object, added alongside the existing backends through the
extension points that already exist (`AstAdapter`, `AstRegistry.register`,
`bundledAstAdapters`), with real compiler validation and tests. What changes is
only *where the generation logic lives* — in a new `src/bend-ast.ts` instead of
in a new `src/lang/bend.ts` `Dialect` — and that alternative was never available
under the brief's own out-of-scope rule (§1.2b). No file owned by another
backend is modified, no shared type changes, no existing test is rewritten.
The one-line addition to `bundledAstAdapters()` is an append to a list, which is
the documented extension point for that list. Phase 3 may proceed.

## 2. Tickets

Every ticket below is anchored on a node or edge that the phase-1 encode
actually produced; the node ids are verbatim from
`evidence/graph/rpg.json` and can be checked with
`evidence/graph/graph-summary.txt`. Descriptions in quotes are the tool's own
wording, not mine.

Two cautions carried forward from `02-graph.md` §3–§4, because they change how
these nodes may be used:

- The graph's `validate` node descriptions are **boilerplate and partly wrong**.
  Six nodes named `verify generated source is well formed_*` all claim the
  function "parses and type checks", which is true of rust, false of lua
  (`luac -p` only parses), and doubly wrong for javascript, which also carries a
  phantom `report missing language toolchain clearly_c8ab3e6a` node although
  `src/lang/javascript.ts:60-64` validates in-process with no external
  toolchain. Tickets T3/T4/T10 therefore take the node as a *pointer to a
  boundary*, and take the parse/type distinction from the measured probe output,
  never from the node description.
- All 724 edges in the artefact are same-file; there are **zero cross-file
  edges**, and 0 of 219 intra-repo relative imports resolved. Cross-file
  dependencies between tickets below are therefore justified by file+line
  evidence, and the fact that the graph could not have supplied them is stated
  rather than hidden.

### T1 — Bend term representation and renderer

- **Graph node:** `construct syntax tree node_c70a8142`
  (`src/python-ast.ts::node`, "Builds a node of the target language syntax tree
  with the supplied fields") and `convert syntax tree to source_c80850ef`
  (`src/python-ast.ts::unparsePython`, "Turns an abstract program tree into
  formatted source text").
- **Evidence:** `src/python-ast.ts` is the precedent for a language whose tree
  types are native rather than shared; `src/ast-adapters.ts:7` imports its four
  entry points directly. Bend's own term type is `HTerm` (`bend2/bend.ts:300`),
  with `TLD = ADT | Def` at `:310` and `Book` at `:311` — the shape the renderer
  must produce text for.
- **Work:** a new `src/bend-ast.ts` defining the subset's term and declaration
  types and a pure `render(program): string`. Emitted subset, each line backed by
  a passing probe: `import Base`; zero or more `def f(+a: U32, …) -> U32:` bodies
  (p17, p18); one `def main() -> IO(Unit):` containing a `do IO<Unit>:` block
  (p1, p14); inside it `+x : U32 = <lit>` and `+s : String = "…"` binders (p11,
  p15), `u : Unit <- IO.print(<expr>)` sequencing (p7), and a final
  `IO.print(<expr>)`. Expressions: `U32` and `String` literals, identifiers,
  `U32.add` (`base.bend:1343`), `U32.sub` (`:1359`), `U32.mul` (`:1364`), `U32.is_eq` (`base.bend:1418`),
  `U32.show` (`base.bend:2135`), `Bool.show` (`base.bend:2166`),
  `String.append` (`base.bend:1774`), and calls to generated defs.
- **Acceptance check that could fail:** a unit test renders a fixed tree and
  asserts byte-exact equality with `evidence/design-probe/p13-arith-nested.bend`
  modulo the `law`/inline-def difference; a second asserts that every binder the
  renderer emits inside a `do` block carries the `+` prefix. Both fail today
  because no renderer exists, and the second fails for any implementation that
  forgets `+` — which p10 proves is a real, reachable defect.
- **Depends on:** nothing.

### T2 — Bounded decision loop that builds the tree

- **Graph node:** `build function body through bounded decisions_ce7b4c1f`
  (`src/python-ast.ts::createBuilder`, "Constructs the statements of one function
  by choosing each construct from a legal set") and
  `keep decision context within budget_4519a285` (same function, "Trims the
  supporting material for each choice so requests remain within the allowed
  size").
- **Evidence:** the contract the loop must satisfy is `AstAdapter.generate`,
  `src/ast-adapters.ts:16` —
  `generate(decisions, state, field, options): Promise<string>`. The rejected
  shared loop is `src/lang/core.ts::generateProgram`, graph node
  `build program through bounded decisions_c05d6bfd`; §1.2 records why it cannot
  be reused.
- **Work:** a generator in `src/bend-ast.ts` that offers only productions legal
  in the subset, so an invalid program is not reachable by any sequence of
  decisions. Bounded by `options.maxSteps` and `options.maxBytes`, mirroring
  `limit program depth and size_9ccb7b00`.
- **Acceptance check that could fail:** a test drives the generator with a
  scripted `DecisionProvider` (pattern of `test/ast-adapters.test.ts:72-83`) and
  asserts the exact source produced; a second exhausts every offered choice at
  the first slot and asserts each resulting program passes `book_load` **and**
  `book_valid`. The second fails if any offered production can produce an
  ill-typed program — the p4/p10 failure mode.
- **Depends on:** T1.

### T3 — `validate` backed by the real Bend 2 checker

- **Graph node:** `verify generated source is well formed_36724074`
  (`src/lang/rust.ts::validate`) and
  `report missing language toolchain clearly_0f76ad5c` (same function,
  "Explains which tool must be installed when the required checker is
  unavailable"). Comparator node:
  `check source acceptance by interpreter_be903247` (`src/lang/lua.ts::parse`).
- **Evidence:** `src/lang/rust.ts:54-62` is the fail-closed precedent — it spawns
  `rustc` and, on `ENOENT`, throws `'Rust validation needs rustc on PATH.'`
  rather than passing. `src/lang/lua.ts:76-80` does the same with
  `'Lua validation needs luac or lua on PATH.'`. `src/ast-adapters.ts:18`
  states the rule: "Reject invalid source; validation is mandatory before a
  write." The Bend entry points are `Bend.book_nil()` (`bend2/bend.ts:966`),
  `Bend.book_load` (`:1013`), `Bend.book_valid` (`:3773`), and
  `Comp.book_owned` (`comp.ts:2866`) — see `01-inspection.md` §4.2.
- **Work:** `validate(source, signal)` writes the source to a scratch file and
  drives the real checker through those four entry points, in process, via
  Node's `.ts` type-stripping — measured at 0.37 s for a full check including
  `base.bend`'s 479 declarations (`01-inspection.md` §4.4). The checker is
  located by an explicit path (env var), **never vendored**, per the licence
  constraint. When it is absent, `validate` **fails closed** with a message
  naming what to install, exactly as rust and lua do.
- **Acceptance check that could fail:** `validate` accepts
  `evidence/bend-probe/ok.bend`; rejects `bad1-syntax-error.bend` with a
  parse-stage error; rejects `bad2-type-error.bend` with a type-stage error;
  and, with the checker path unset, rejects *valid* source with the
  toolchain-missing message rather than accepting it. The last assertion is the
  one that catches a validator that silently degrades to a no-op.
- **Compiler blocker status:** none. `01-inspection.md` §4.4 records a measured
  full parse + type-check + ownership check on this CPU-only VPS with no Bun, no
  GPU and no paid resources. "Compiler-backed checks" are therefore satisfiable
  here, and no hand-written substitute checker is written or permitted. The
  claim is limited to the **checking** path: `Comp.compile_book` and the C/CUDA
  back ends were not attempted and are not claimed.
- **Depends on:** nothing (can be built and tested against the probe fixtures
  before T1 exists).

### T4 — Separate the three stages in the returned result and reject holes

- **Graph node:** `recognize unfilled placeholder marker_2578e2e5`
  (`src/lang/core.ts::isPending`) and
  `detect unfinished parts of program_90cc9494` (`src/lang/core.ts::hasHole`,
  "Reports whether any position in a program subtree remains undecided").
- **Evidence:** Bend's own CLI gates on holes separately from the three checks —
  `main.ts:591-595`, `book.hols + book.open > 0` → "N TODOs found. The code is
  incomplete, and not a valid proof yet." The measured stage separation is
  `01-inspection.md` §4.5: probe A fails `book_load`, probe B passes
  `book_load` and fails `book_valid`, probe C passes both.
- **Work:** the internal checker call returns which stage failed, so callers and
  test names can say `parse`, `type`, `owned`, or `holes` and never a blended
  "valid". A program with `hols + open > 0` is rejected.
- **Acceptance check that could fail:** a test asserts the stage label for each
  of the four rejection classes, with four distinct expected labels. A program
  containing a `?hole` is rejected with label `holes`, not `type`. An
  implementation that returns a single boolean fails this test.
- **Depends on:** T3.

### T5 — The adapter object and its registration

- **Graph nodes:** `list built in language adapters_1a088811`
  (`src/lang/index.ts::bundledAstAdapters`),
  `register bundled language adapters_fde9a81a`
  (`src/ast-adapters.ts::AstRegistry::constructor`),
  `validate adapter identity_9c4922f3`,
  `validate adapter extensions and languages_f1ee2eae`,
  `require generation and validation capabilities_b6460a3a`, and
  `reject conflicting extension or language claims_4fa737a4` (all
  `src/ast-adapters.ts::AstRegistry::register`).
- **Evidence:** `src/ast-adapters.ts:32-40` is the full registration contract —
  id must match `/^[a-z][a-z0-9-]{0,63}$/` (`:32`), be unique (`:33`),
  extensions must match `/^\.[a-z0-9]+$/` (`:34`), languages

  `src/lang/index.ts:9` (javascript, typescript, c, rust, go, lua, ruby) plus

- **Work:** `export const bendAstAdapter: AstAdapter = { id: 'bend',

- **Depends on:** T2, T3.

### T9 — Rejection tests

- **Graph node:** `reject constructs unsupported by language_52341516`
  (`src/lang/rust.ts::stmt`, "Fails when a statement has no faithful equivalent
  in the target language"); comparator `screen candidate body for defects_bcb8ebc2`
  (`src/python-ast.ts::checkCandidate`) and
  `avoid executing untrusted candidate code_0fc602c5` (same function,
  "Assesses candidates statically so generated code never runs during

- **Evidence:** the fixtures already exist and their failures are already

### T10 — Known limits and the three separate claims, written down

- **Graph node:** the six nodes named `verify generated source is well formed_*`
  (`_36724074` rust, `_fcc31783` go, `_9c5acc4c` javascript, `_8f979b3c` lua,
  plus c and ruby), all of which carry the identical description "Confirms that
  generated source parses and type checks before it is accepted or written".
- **Evidence:** that description is false for lua, whose `validate`
  (`src/lang/lua.ts:76-80`) only runs `luac -p` — a parse check — and for
  javascript, whose `validate` (`src/lang/javascript.ts:60-64`) runs
  `ts.transpileModule` in process and filters syntactic diagnostics only. The
  graph's own vocabulary blends parse and type, which is precisely the conflation
  this pilot must avoid.
- **Work:** a limits section in the phase-3 report stating, separately and with
  separate evidence: (1) **parse validity** — what `book_load` accepted;
  (2) **typing and proofs** — what `book_valid` and `book_owned` accepted, and
  that a passing `book_valid` on a program containing no proof obligations is
  not evidence of a proof; (3) **semantic correctness** — **not claimed**, since
  nothing generated is executed. Test names, report lines and commit messages
  must not let any one stand for another. Request counts are reported in their
  own section and are explicitly not a quality result.
- **Acceptance check that could fail:** a lint-style test over the phase-3 test
  file asserting no test name contains "correct"/"works" for a
  parse-or-type-only assertion. It fails the moment a test is named
  `bend programs are correct` on the strength of a `book_valid` pass.
- **Depends on:** T3, T4, T9.

### T11 — Retain a candidate baseline

- **Graph node:** `derive candidate names from objective_586bcfa3`
  (`src/python-ast.ts::vocabulary`, "Extracts identifiers, words, strings, and

## 3. Explicitly not in phase 3

Recorded as follow-ups, not done here.

- **`generateProject` / `validateProject`.** Optional on the interface
  (`src/ast-adapters.ts:20-21`); `src/generation.ts:47` only selects an adapter
  for multi-file work if it implements both. Omitting them means Bend is simply
  never chosen for a project, with no change to any existing behaviour. Graph
  node `emit single file or project layout_5c027112`.
- **Any change to `src/lang/core.ts` or any existing backend.** Out of scope by
  the brief and unnecessary under the native-AST choice.
- **The `Dialect` fuzz ladder.** `test/lang-fuzz.test.ts:44-47` enumerates
  `Dialect` values; a native adapter is not one, so that file is not touched and
  no existing test is rewritten.
- **`match`, ADTs, recursion, `law` declarations, proofs, IO beyond
  `IO.print`.** p5 and p16 show `match` and recursion type-check, so these are
  reachable later; they are left out to keep the first slice deliberately tiny.
- **Code generation back ends.** `Comp.compile_book`, the C and CUDA emitters,
  and `Comp.io_run` are not exercised. Nothing generated is run.
- **Broader Bend adoption, publishing, packaging, the full eval ladder, and any
  change outside this project.**
